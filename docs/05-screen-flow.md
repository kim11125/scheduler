# 05. 화면 흐름 설계

## 1. 화면 목록 및 라우팅 경로

| 경로 | 화면명 | 인증 | 접근 가능 대상 |
|------|--------|------|----------------|
| `/login` | 로그인 | 불필요 | 모든 사용자 |
| `/register` | 회원가입 신청 | 불필요 | 모든 사용자 |
| `/pending` | 계정 상태 안내 | 필요 | PENDING / REJECTED / DISABLED |
| `/` | 개인 스케줄 메인 | 필요 | USER + ACTIVE |
| `/schedules/new` | 일정 등록 | 필요 | USER + ACTIVE, ADMIN + ACTIVE |
| `/schedules/:id/edit` | 일정 수정 | 필요 | 작성자 본인 또는 ADMIN |
| `/admin` | 관리자 대시보드 | 필요 | ADMIN + ACTIVE |
| `/admin/schedules` | 관리자 전체 일정 | 필요 | ADMIN + ACTIVE |

---

## 2. 로그인 전 접근 가능 화면

- `/login`
- `/register`

그 외 모든 경로는 미인증 상태에서 접근 시 `/login`으로 리다이렉트한다.

---

## 3. 로그인 후 상태별 화면 분기

로그인 성공 후 `/api/auth/me` 응답을 기준으로 분기한다.

```
POST /api/auth/login 성공
        ↓
GET /api/auth/me
        ↓
role === 'ADMIN' && status === 'ACTIVE'  → /admin
role === 'USER'  && status === 'ACTIVE'  → /
role === 'USER'  && status === 'PENDING' → /pending
role === 'USER'  && status === 'REJECTED'→ /pending
role === 'USER'  && status === 'DISABLED'→ /pending
```

> `/pending` 화면에서 status에 따라 다른 메시지를 보여준다.

## 4. 관리자 화면 흐름

```
/admin (관리자 대시보드)
  ├── 승인 대기 목록 (PENDING 사용자)
  │     ├── [승인] 버튼 클릭 → PATCH /api/admin/users/{id}/approve → 목록 갱신
  │     └── [거절] 버튼 클릭 → PATCH /api/admin/users/{id}/reject → 목록 갱신
  │
  ├── 전체 사용자 목록
  │     ├── status 필터 (전체/ACTIVE/PENDING/REJECTED/DISABLED)
  │     ├── [비활성화] 버튼 (ACTIVE 사용자에게만 표시)
  │     └── [재활성화] 버튼 (DISABLED 사용자에게만 표시)
  │
  └── [전체 일정 보기] 버튼 → /admin/schedules

/admin/schedules (관리자 전체 일정 조회)
  ├── 사용자 필터 (드롭다운)
  ├── 날짜 필터 (날짜 선택)
  ├── 카테고리 필터 (드롭다운)
  ├── 일정 목록 테이블
  │     ├── 일정 행 클릭 → 상세 모달 또는 인라인 수정 패널
  │     ├── [수정] 버튼 → PUT /api/schedules/{id}
  │     └── [삭제] 버튼 → DELETE /api/schedules/{id} → 목록 갱신
  └── [관리자 대시보드로] 버튼 → /admin

관리자 본인 일정 등록:
  /admin 또는 /admin/schedules에서 [내 일정 추가] 버튼 → /schedules/new
```

## 5. 일반 사용자 화면 흐름

```
/ (개인 스케줄 메인)
  ├── 월간 캘린더
  │     ├── 이전/다음 월 이동 버튼
  │     ├── 날짜 셀에 일정이 있으면 카테고리 도트 표시
  │     └── 날짜 클릭 → 하단 패널에 해당 날짜 일정 목록 표시
  │                    → [일정 추가] 버튼 → /schedules/new?date=YYYY-MM-DD
  │
  ├── 선택 날짜 일정 목록 (하단 패널)
  │     ├── 일정 카드 클릭 → /schedules/:id/edit
  │     └── [+ 일정 추가] 버튼 → /schedules/new?date=YYYY-MM-DD
  │
  └── 상단 헤더
        ├── 내 정보 (이름 표시)
        └── [로그아웃] 버튼

/schedules/new?date=YYYY-MM-DD (일정 등록)
  ├── URL query의 date가 날짜 기본값으로 세팅
  ├── 날짜 변경 가능 (날짜 선택기)
  ├── 제목 입력
  ├── 카테고리 라디오 (야구/농구/축구/여자배구/남자배구/기타)
  ├── 야구 선택 시 홈/원정 라디오 (필수) 추가 표시
  ├── 메모 입력 (선택)
  ├── [저장] → POST /api/schedules → 성공 시 / 로 이동
  └── [취소] → 이전 페이지로 이동 (또는 /)

/schedules/:id/edit (일정 수정)
  ├── 기존 일정 데이터 로딩 (GET /api/schedules/:id)
  ├── 날짜 변경 가능
  ├── 제목 수정 가능
  ├── 카테고리 변경 가능
  ├── 야구 선택 시 홈/원정 라디오 표시
  ├── 메모 수정 가능
  ├── [저장] → PUT /api/schedules/:id → 성공 시 / 로 이동
  ├── [삭제] → 확인 다이얼로그 → DELETE /api/schedules/:id → / 로 이동
  └── [취소] → / 로 이동
```

## 6. 모바일 UI 구성

모바일 우선 설계. 기준 뷰포트: 375px 이상.

### 6-1. 메인 화면 (`/`) 레이아웃

```
┌─────────────────────────────┐
│ [헤더] 이름  |  로그아웃     │  ← 고정 상단
├─────────────────────────────┤
│                             │
│     월간 캘린더              │  ← 상단 60% 영역
│  [< 2026.06 >]              │
│  일 월 화 수 목 금 토        │
│  ... 날짜 셀 ...             │
│                             │
├─────────────────────────────┤
│ 선택 날짜: 6월 1일           │  ← 하단 패널 (드래그 업 또는 고정)
│ ┌──────────────────────┐    │
│ │ 두산 vs LG (야구/홈)  │    │
│ └──────────────────────┘    │
│ ┌──────────────────────┐    │
│ │ 농구 경기             │    │
│ └──────────────────────┘    │
│ [+ 일정 추가]               │
└─────────────────────────────┘
```

### 6-2. 날짜 클릭 후 UX 흐름

1. 캘린더에서 날짜 셀 탭
2. 하단 패널이 해당 날짜의 일정 목록으로 교체
3. 패널 하단의 **[+ 일정 추가]** 버튼 탭
4. `/schedules/new?date=YYYY-MM-DD` 화면으로 이동 (전체 화면 전환)

> 갤럭시 기본 캘린더 앱처럼 날짜 탭 → 패널 전환 → 빠른 입력 진입을 목표로 한다.

### 6-3. 일정 등록/수정 화면 레이아웃 (전체 화면)

```
┌─────────────────────────────┐
│ [← 취소]     일정 등록       │  ← 상단 네비게이션
├─────────────────────────────┤
│ 날짜                         │
│ [2026-06-01          📅]    │
│                             │
│ 제목                         │
│ [___________________]       │
│                             │
│ 카테고리                     │
│ ○ 야구  ○ 농구  ○ 축구       │
│ ○ 여자배구  ○ 남자배구  ○ 기타│
│                             │
│ ← 야구 선택 시에만 표시 →     │
│ 홈/원정                      │
│ ○ 홈  ○ 원정                │
│                             │
│ 메모                         │
│ [                    ]      │
│ [                    ]      │
│                             │
│ [        저장        ]      │  ← 하단 고정 버튼
└─────────────────────────────┘
```

### 6-4. 관리자 화면 모바일 구성

- `/admin`: 승인 대기 목록 → 전체 사용자 목록 순으로 스크롤
- `/admin/schedules`: 필터 영역 접기/펼치기, 목록은 카드형

## 7. 라우터 가드 로직 (Vue Router)

```
모든 라우트 접근 시:
  1. localStorage에 accessToken 있는지 확인
  2. 없으면 → /login 리다이렉트
  3. 있으면 → GET /api/auth/me 호출
     - 실패(401) → localStorage 토큰 삭제 → /login 리다이렉트
     - 성공 → user.role + user.status 기준 분기
       - 목적지가 /admin/* 이고 role !== 'ADMIN' → /
       - 목적지가 /schedules/* 이고 status !== 'ACTIVE' → /pending
       - status가 PENDING/REJECTED/DISABLED이고 목적지가 / 또는 /schedules/* → /pending

공개 라우트 (/login, /register):
  - accessToken이 있으면 /api/auth/me 호출 후 자동 분기 (재로그인 방지)
```

> 라우터 가드는 UX 보호 목적이며, 실제 권한 강제는 백엔드 API에서 처리한다.
